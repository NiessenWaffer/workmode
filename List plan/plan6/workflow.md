## Precise User Flow (The Analyze -> Implement Pipeline)

### Phase 1: Intake & Analyze
1. **Trigger:** User provides a task (e.g., "Fix the login bug" or "Build a new report page").
2. **Action (Analyze Mode):** The LLM boots into **Analyze Mode**.
3. **Action:** The LLM reads `standard_coding.md` to establish the enterprise constraints.
4. **Action:** The LLM uses `MAP` and `SIG` to map the relevant Laravel Controllers, Vue components, and Services.
5. **Action:** The LLM analyzes the complexity and identifies risks (e.g., "This touches a core legacy user table").
6. **Output:** The LLM stops and outputs a strategy. "Analysis complete. The bug is in `AuthController`. I will forward this to the Debugger Mode for a safe, minimal patch."

### Phase 2: Routing & Handoff
1. **Decision Gate:** Based on the analysis output, the orchestrator routes to the correct implementation mode.
   - *If Bug/Error:* Route to **Debugger Mode**.
   - *If Feature/Refactor:* Route to **Developer Mode**.

### Phase 3: Execution
1. **Trigger:** Developer or Debugger mode activates with the Analyze context.
2. **Action:** Read `standard_coding.md` (specifically the Output Style and File Reading Safety sections).
3. **Action:** Execute the precise fix using surgical `replace` operations.
4. **Action:** Provide a step-by-step explanation of what changed and the rollback strategy, as mandated by the enterprise standard.

## Verification Flow
- **Analyze Constraint Check:** If a user asks the Analyze mode to "write the fix for me," the AI MUST refuse and state it is in read-only analysis mode and will hand off to the Developer mode.
- **Standard Enforcement Check:** Any code generated by Developer or Debugger MUST NOT use Laravel 10+ syntax, strictly remaining backward compatible with Laravel 7.

## Risks & Unknowns
- **Context Loss During Handoff:** Ensure that the strategy generated by Analyze mode is passed perfectly into the prompt/context window of the Developer/Debugger so they do not have to re-map the codebase.
